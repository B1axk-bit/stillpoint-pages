# 事实层细节：快照、数据源和账本

> SKILL.md 第 2 节的展开。要拉数据、快照有问题、网络被拦、要查指标 ID 或吸引子读法细节时读这份。

## 一键快照

脚本是用户 Mac 上的 `~/学习/invest_snapshot.py`，平时由定时任务自动运行（见下面"谁来运行"）；手动运行时，日报回看天数用 `--days N`，主题用 `--topics liquidity ai-infrastructure energy`。它一次拉齐下面 ①②③ 三个来源：行情清单、A 股行业板块排行、两个来源的默认指标组、最新日报的关键章节和 ARGUS 更正记录。吸引子指标会自动标上读法和置信度，输出一份带检索时间戳的事实账本（`~/学习/snapshots/snapshot_*.md` 和 `.json`）。

为什么首选它：手动拼接口地址费时间，还容易漏掉指标；脚本每次拉的是同一组指标，前后几次的快照才能直接比较。

**和上次快照比**：每次运行时，脚本会自动找到 `snapshots/` 里的上一份快照，在新快照的最前面写一节"和上次快照比"，列出：
- 吸引子：方向翻转、置信度换档（例如从"中"掉到"边沿"）、新出现的"转入上升"或"转入下降"，以及读数变动 0.15 以上的指标；
- ARGUS：出了新观测期的指标；
- 行情：变动超过 1 个百分点、而且更新时间变了的品种，最多列 10 个；
- ARGUS 新发的报告。

这一节就是一屏简报里"状态变化"的来源。写"没有明显变化"也是有效信息，说明上次的判断不用动。要比较任意两份旧快照，用 `python3 invest_snapshot.py --compare 旧.json 新.json`，这条命令不联网。0.15 和 1% 两个阈值是我们定的研究规则，觉得太吵或太静就改脚本。

**常用开关**：`--days N` 日报回看天数，`--topics` 指定主题，`--no-prices` 不拉行情，`--no-watchlist` 不拉观察清单，`--no-sectors` 不拉板块排行，`--no-reports` 不拉日报。

**谁来运行**：用户 Mac 上的定时任务自动跑（10/15 装好，launchd 任务 `com.b1ack.invest-snapshot`），不要再请用户手动运行。
- **定时**：周一到周五 08:40、11:35、15:10、21:00，周六 08:40（补周五美股收盘）。Mac 睡眠时错过的，唤醒后补跑一次；关机时不跑。
- **先看现成的**：读 `~/学习/snapshots/auto_status.txt`。`last_end` 离现在不久、问题又不需要更新的数据，就直接读 `latest` 指向的快照。
- **要最新数据时**：用文件夹工具往 `~/学习/auto/request.txt` 写一行新内容（例如 `req-20261016-0930`），Mac 会马上跑一次。然后反复读 `auto_status.txt`，等到 `request_token` 等于刚写的那行、`exit_code=0`，再读 `latest`。一次大约 1 到 2 分钟。
- **几分钟没动静**：Mac 可能在睡眠、关机或断网。用最近一份快照，并在报告开头写明快照时点。
- **出错时**：运行记录在 `snapshots/auto.log`，最近一次的报错在 `snapshots/.auto_last_err.txt`。
- **为什么只能这样触发**：文件夹工具的 shell 是一台 Linux 虚拟机，自己连不了外网，也调不了 launchctl；`request.txt` 是它唯一能让 Mac 跑脚本的办法。
- **安装和卸载**：只能由用户自己在终端运行，`bash ~/学习/install_auto_snapshot.sh` 安装或更新，加 `uninstall` 卸载。Claude 的自动模式会把装定时任务当作需要用户授权的持久化操作拦下，不要绕。
- 手动运行仍然可用：`cd ~/学习 && python3 invest_snapshot.py`。

定时脚本 `auto/run_snapshot.sh` 和安装脚本的副本在项目文件 `skills/stillpoint/scripts/auto/`。脚本文件名 `invest_snapshot.py` 和定时任务名 `com.b1ack.invest-snapshot` 沿用旧名，改名不需要重装。

脚本的副本在项目文件 `skills/stillpoint/scripts/invest_snapshot.py`。快照拉完后，再按需补下面的手动查询和公开报道。

## 数据源（按优先级）

**① ARGUS**（`https://argusx.fun/api/v1/`，只用免密 GET，不需要 key）

- 日报：`search?type=report&kind=daily&lang=zh&from=YYYY-MM-DD`。重点读 liquidity 和 ai-infrastructure 两个主题。用 `content/ID` 先拿目录，再用 `section=` 只读"当前状态""Thesis Stop / 证伪条件""下一步要盯的变量"几节。`fullReport=false` 表示只有摘要。
- 周报：`kind=weekly`，看 china 和 energy。
- 默认指标组（`metrics/ID`，不要加 history，除非真的在做历史分析）：
  - 利率与流动性：`treasury-2y`、`treasury-10y`、`real-yield`、`term-premium-10y`、`funding-pressure`（SOFR−IORB）、`ofr-credit-stress`、`bank-reserves`、`tga`
  - AI 主题加：`hyperscaler-capex`、`supplier-revenue`
  - 能源主题加：`diesel-gulf-spot`、`wti-spot`、`crack-spread`、`distillate-stock`
  - 中国：先用 `catalog?topic=china` 查 ID
- 作者观点：`search?type=perspective`，挑 1–2 条论点真正不同的。
- 引用有争议的数字之前，先查 `https://argusx.fun/api/corrections`。

**② 吸引子宏观接口**（`POST https://jackal.attractorcap.com/crusty/macro/latest`，请求头 `apikey` 读自 shifenxiyin-perspective skill 目录下的 `macro_apikey.txt`，body 是 `{"sec_ids": [...]}`）

默认指标组：

- 美国：物价 `att_00000064`、资金利率 `att_00000070`、资金利率预警 `att_00003480`、货币政策倾向 `att_00000985`、财政政策力度 `att_00000372`、信用环境 `att_00000067`、信用环境预警 `att_00000983`、市场风险偏好 `att_00000984`、消费就业周期 `att_00000061`、制造业周期 `att_00000058`
- 全球：美元流动性 `att_00001069`、风险偏好指数 `att_00003416`
- 中国：物价 `att_00000042`、流动性 `att_00001068`、信用环境 `att_00000045`、外部金融条件 `att_00003413`、总需求 `att_00000039`

**读法词典**（依据吸引子 skill 的 `references/08-tools.md`）：

- **正负号是方向**：正 = 这个指标语义的正侧（扩张、偏松、上行），负 = 负侧（收缩、偏紧、下行）。
- **绝对值是置信度**：表示底层子指标里有多大比例支持这个方向。
  - ≥ 0.8：强，几乎所有底层指标同向，方向可信，往往在自我强化。
  - 0.6–0.8：中。
  - 0.2–0.6：**边沿**，支持这个方向的只是勉强过半，少数底层指标掉头就可能反转。这是最该设路标验证、不押重注的状态。
  - < 0.2：没有明确方向。`state=中性` 表示方向在重新选择，不要当成转向信号。
- **`stateChange`**："转入上升"或"转入下降"才是拐点。置信度高、又连续同向的，才算强路标。

| 指标 | 正侧含义 | 负侧含义 |
|---|---|---|
| 物价（美国、中国、欧洲） | 物价上行压力 | 物价下行 |
| 资金利率 | 利率上行（钱变贵） | 利率下行 |
| 货币政策倾向 | 偏松 | 偏紧 |
| 财政政策力度 | 扩张 | 收缩 |
| 信用环境 / 信用价格 | 信用扩张 | 信用收缩 |
| 流动性（全球美元、中国、欧洲） | 扩张 | 收缩 |
| 风险偏好（美国、全球、中国） | 风险偏好上升 | 风险偏好下降 |
| 外部金融条件 | 偏松 | 偏紧 |
| 周期类（总需求、制造业、消费就业） | 扩张 | 收缩 |
| **"预警"类** | 领先信号指向正侧 | 领先信号指向负侧 |

"预警"类的含义是推断：源文档只把它归为同一个框架概念，没有单独定义，按同一套正负号规则来读。用的时候要标注"推断"，并用 ARGUS 或官方的硬数据去验证。

**判读示例**（2026-10 的读数）：美国信用环境 +0.75，表示信用在扩张，置信度中等；同一时间信用环境预警是 −1.0，表示领先信号 100% 指向收缩。两者放在一起读：信用现在还松，但前瞻信号一致看紧，这就是最值得盯的背离。

**③ 行情**（脚本自动拉，免密 GET）

- **来源**：东方财富行情接口为主（`push2.eastmoney.com`，一次批量请求）。拉不到的品种逐个改用 Yahoo（`query1.finance.yahoo.com/v8/finance/chart`）。两个都是非官方接口，账本的核验列写"行情接口"，可信度低于财政部、交易所这类官方数据。
- **覆盖**：
  - 美元和汇率：美元指数、欧元、日元、离岸人民币
  - 黄金和原油：COMEX 黄金、伦敦金、布伦特、WTI
  - 美股：标普 500、纳指、费城半导体、VIX
  - 亚太：日经、KOSPI、台湾加权、恒生、恒生科技
  - A 股：上证、深成、创业板、科创 50、沪深 300
  - 观察清单：《AI 生态组织者研究清单》里的美股、A 股个股和 ETF，只用来跟踪，不是推荐；不想要时加 `--no-watchlist`
  - A 股行业板块：东方财富行业板块的全量排行（约 496 个，含二、三级行业），快照里写上涨、下跌家数，领涨、领跌和成交额最大各 5 个。三级行业很细，涨跌两端常被小板块占满，所以要看"成交额最大"那行，才知道钱实际集中在哪。10/15 17:19 第一次真实运行核对过，板块名和涨跌幅正常
  - **东方财富会断开连接**：10/15 晚上行情接口和板块接口都出现过直接断开。脚本会换备用服务器（17.push2、82.push2）和 curl 再试，行情再不行改走 Yahoo。板块接口更容易断，失败时快照会沿用最近一份拉到的排行，并写明是哪个时点的；引用时要写那个时点，不能当成当前数据
- **沪深两市成交额**：用上证指数和深证综指的成交额相加估算。
- **怎么读**：
  - 盘中拉到的是实时价，不是收盘价，以"更新时间"一列为准；
  - 美股和欧洲品种在北京时间白天显示的是上一个交易日的收盘；
  - Yahoo 的 A 股 ETF 日线常常还没收进当天那根，v0.4.1 起昨收按日期对齐。修正前会算成两天的涨跌幅，例如 10/15 的 515880 显示 −8.92%，实际是 −4.93%；
  - "接口名"和"名称"对不上，说明代码配错了，改脚本里的 `PRICE_SET` 或 `WATCHLIST`。10/15 已经逐行核对过 47 个品种：标普和纳指的收盘数和新闻完全一致；费城半导体在东方财富没有报价，改走 Yahoo。
  - **收盘数优先于新闻描述**：新闻里"约 −3.5%""小跌"这类说法往往是盘中数。10/14 的报告就因此把 ASML 写成"小跌"，实际收盘是 −3.94%。
- **没覆盖的**：北向资金和概念板块（例如 CPO、存储）。据我了解，北向资金从 2024 年起不再实时披露，所以脚本不拉。这两项继续用公开报道补。

**④ 公开报道**（WebSearch）：补板块、个股新闻和催化事件，以及行情接口拉不到的收盘数。至少用两家来源交叉核对。盘中数和收盘数分开写。有官方数据（财政部、Fed H.4.1、BLS）时，以官方为准。

## 网络被拦截时

云端环境的网络白名单可能拦截 argusx.fun、jackal.attractorcap.com 和两个行情接口（push2.eastmoney.com、query1.finance.yahoo.com），返回 403。连到用户 Mac 上的文件夹工具，走的也是同一份白名单，同样会被拦。可行的办法有两个：

1. 用 Mac 上的自动快照（见上面"一键快照"），Claude 读取结果文件。这是默认做法。
2. 请用户在项目设置里给云端环境加上这四个域名（Allowed domains），再加环境变量 `ATTRACTOR_API_KEY`。只对之后新开的会话生效。

在 Mac 终端运行时，ARGUS 也可能返回 403。10/15 第一次运行就是这样：吸引子 19 项全部正常，ARGUS 全部 403。原因是 ARGUS 拦截 Python 默认的 User-Agent：加上如实的身份标识后，第二次运行用 urllib 就全部拿到了。脚本被拦时还会自动换 macOS 自带的 curl 再试一次，快照开头会写上"ARGUS 通道"是哪一种。两种方式都被拦时，只会显示一行错误摘要（例如防火墙页面的标题），并停止继续请求。Claude 根据这行摘要判断原因：是被防火墙拦了、所在地区受限，还是本机代理的问题。

两个办法都不行时，用公开报道完成分析，并在报告开头写明缺了哪些数据，以及这对信心有什么影响。

## 账本格式

| 项目 | 数值和单位 | 观测期 | 检索时点 | 变化 | 来源和核验状态 |
|---|---|---|---|---|---|

记账规则：
- 发布日、观测日、检索日是三个不同的日期，不要混。**检索时点**要写到小时。同一份报告里，宏观数据和盘面数据经常不是同一时刻拉的，比如宏观数据在亚洲开盘前拉、盘面数据是午盘数，这时要在数据说明里点出来。重大交易时段结束后，要重新取数再下结论。
- 盘中数和收盘数分开标注。
- 缺值不是零。旧的观测值不是当前行情。
- 标为 `unverified` 或 `report-only` 的数字只能作背景，不能作决策依据。
- 估算类数据（期限溢价、OFR 指数）要标"估算"；有滞后的要写滞后几天。
- ARGUS 的 `change` 是指标自身单位的算术差，不是涨跌幅，也不是看多看空的结论。

证据预算（写进结论的决定性证据限定 3–5 条）见 SKILL.md 第 2 节。
