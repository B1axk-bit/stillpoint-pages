# 回看打分

> SKILL.md 第 8 节的展开。

**什么时候做**：用户说"回看一下""之前的判断对不对"，或者生成简报时发现案例日志里有案例到了回看日。回看日一般设在 1–4 周后，或者紧跟在关键事件之后，比如 FOMC 的第二天。

**怎么做**：
1. 先跑一次快照，拿到当前价格和指标；
2. 和案例里的锚点、路标读数对照，补上"后来实际怎么走"；
3. 打三项分，每项 0 / 1 / 2：
   - **方向**：立场在回看窗口里站不站得住。要和基准比，美股用标普 500，半导体用 SMH，A 股用沪深 300。"等待"的标准不一样：只看解除条件出现之前，价格有没有比锚点高出 5% 以上，高出了就说明等的东西不对；
   - **路标**：路标有没有先于价格变化。价格先动、路标没反应，就是路标选错了；
   - **机制**：事后证据有没有证实当时的机制判断；
4. 写清错在哪一层（事实、机制、决策）和要改什么。

完整的打分表和阈值在 `analysis/案例日志.md` 开头。阈值是研究规则，不是历史定律。

**为什么要打分**：没有记录，就分不清是框架对了还是运气好。每积累 4 个已回看的案例，统计一次哪一层错得最多，再去改这份 skill 的对应部分。10/14 的 ASML 订正就是第一条事实层记录，直接促成了 v0.3 的价格层。
